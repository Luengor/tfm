\section{Métodos}
\label{sec:metodos}
En esta sección se detalla la metodología seguida para evaluar tanto el
rendimiento como la calidad de los sistemas de extracción de características y
algoritmos de agrupamiento para nuestro banco de imágenes de grafiti.

\subsection{Arquitectura del entorno de evaluación}
\label{subsec:arquitectura_pipeline}
% Anotación: Describir la arquitectura modular del pipeline implementado.
% Mencionar cómo las clases abstractas en abstractions.py permiten el desacoplamiento.
% Explicar el flujo de datos desde la imagen en bruto hasta el resultado del clustering.
Para la evaluación de cada uno de los sistemas, se ha implementado un
\textit{pipeline} modular en Python, que permite la integración de diferentes
componentes de almacenamiento, extracción de características, reducción de
dimensionalidad y agrupamiento a través de un archivo de configuración JSON,
así como parámetros adicionales que permiten personalizar cada una de las
etapas del proceso. Los módulos que componen el sistema se han diseñado como
una interfaz que define los métodos necesarios para su funcionamiento.

El proceso de evaluación sigue un flujo de datos estructurado que se divide en
dos etapas principales: la fase de extracción de características y la fase de
agrupamiento y evaluación.

En la primera etapa, el sistema comienza con la ingesta de imágenes en bruto.
Durante esta fase, el sistema aplica el modelo de extracción de características
seleccionado para generar vectores de características (\textit{embeddings}) a
partir de las imágenes. Estos vectores luego se almacenan en el entorno de
almacenamiento configurado.

Durante la segunda etapa, el sistema recupera los vectores de características
almacenados y aplica la técnica de reducción de dimensionalidad seleccionada
(en el caso de que se haya configurado, puesto que esta es opcional). Sobre los
vectores resultantes, se ejecuta el algoritmo de agrupamiento configurado para
generar los \textit{clusters}. Finalmente, se evalúa la calidad de los grupos
generados utilizando las métricas definidas en la sección
\ref{subsec:metricas}.

De forma adicional, durante la segunda etapa se pueden realizar consultas de
similitud para evaluar la eficiencia y precisión del sistema en la recuperación
de imágenes similares a una imagen de consulta dada.

Durante cada una de estas operaciones, se registran métricas de tiempo y
consumo de recursos para su posterior análisis comparativo entre las diferentes
configuraciones probadas.
